# VS Codeでテストをデバッガー停止する手順

## このプロジェクトの仕組み

テストは、次の順序で動きます。

1. `test/**/*.ts`と`server/**/*.ts`を`dist/`へTypeScriptコンパイルする
2. `dist/test/**/*.test.js`をNode.js標準テストランナーで実行する

そのため、VS Codeのデバッガーは`test/tasks-api.test.ts`を直接実行するのではなく、`dist/test/tasks-api.test.js`を起動します。`tsconfig.json`のソースマップによって、停止位置は元のTypeScriptファイルへ対応付けられます。

## 事前準備

1. VS Codeでこのプロジェクトのフォルダーを開く
2. Node.js 22以降が選択されていることを確認する
3. ターミナルで一度だけ依存関係をインストールする

```bash
npm install
```

リポジトリには、次のデバッグ設定を追加しています。

| ファイル | 役割 |
| --- | --- |
| `.vscode/launch.json` | Node.jsテストデバッガーを起動する |
| `.vscode/tasks.json` | 起動前にTypeScriptを`dist/`へコンパイルする |
| `tsconfig.json` | TypeScriptとJavaScriptを対応付けるソースマップを生成する |
| `package.json` | デバッグ用の`compile:test`スクリプトを定義する |

## ブレークポイントで止める

1. [テストファイル](../test/tasks-api.test.ts)または[APIハンドラー](../server/api/tasks.patch.ts)を開く
2. 行番号の左側をクリックして赤いブレークポイントを置く
3. **実行とデバッグ**ビューを開く
4. 構成で`テスト: tasks-api`を選ぶ
5. `F5`を押す
6. 初回は起動前タスクが実行され、その後テストが開始される

不正なタイトルの処理を確認する場合は、`server/api/tasks.patch.ts`の空白チェック内、またはテストの次の行にブレークポイントを置きます。

```ts
const response = await callTasksApi("   ");
```

停止後は、左側のデバッグパネルでローカル変数、コールスタック、ブレークポイント、ウォッチ式を確認できます。`F10`は次の行、`F11`は関数内部へ進む操作です。

## テストを限定する

設定は`tasks-api.test.ts`だけを起動するため、通常はこのファイル内の2テストが対象です。さらに一つのテストだけに絞る場合は、テスト名に一時的に`.only`を付けます。

```ts
test.only("第01章: titleが空ならNuxtサーバーAPIは400とエラーJSONを返す", async () => {
```

デバッグが終わったら`.only`を必ず削除してください。`.only`を残すと、通常の`npm test`でも他のテストが実行されません。

## ブレークポイントで止まらない場合

| 症状 | 確認・対処 |
| --- | --- |
| `dist`がない | `F5`で起動し直す。起動前タスクがコンパイルを実行する |
| `.ts`ではなく`.js`が開く | `sourceMap: true`と`outFiles`が設定されているか確認する |
| テストが一瞬で終わる | ブレークポイントを`test`のコールバック内かハンドラー内に置く |
| 以前のコードが実行される | コマンドパレットから「タスク: 実行中のタスクを終了」を選び、再度`F5`を押す |
| 通常のテスト結果も確認したい | ターミナルで`npm test`を実行する |

## デバッグ後の確認

ブレークポイントを削除または無効化し、通常のテストを実行します。

```bash
npm run typecheck
npm test
```

期待される結果は、2テストが成功し、失敗が0件になることです。
